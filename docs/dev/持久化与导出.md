# 持久化与导出

本地优先意味着「存储」和「导出」是数据离开内存的仅有两条路径。本文给出存储键、保存时序、自动快照规则、导入校验，以及 SVG / PNG / PDF / Markdown 四种导出的实现约定。

## 存储分工

| 键 | 内容 | 读写位置 |
| --- | --- | --- |
| `OpenBoard:v1` | 完整 `BoardsFile`（全部白板 + `activeId` + `settings`） | `src/features/storage/file.ts` |
| `OpenBoard:favorites` | 收藏数组 `{ type: 'shape' \| 'template', id }[]` | `src/features/storage/favorites.ts` |

- 两个键互不依赖：清掉收藏不影响白板，清掉白板不影响收藏。
- `loadFile()` 的失败路径只有一条——`try/catch` 静默回落到 `defaultFile()`。首次访问、隐私模式禁用存储、JSON 损坏都走这里。
- `saveFile(file)` 是 `localStorage.setItem(KEY, JSON.stringify(file))`，异常向上抛给调用方处理。
- 收藏由 `useFavorites()`（`src/app/hooks/useFavorites.ts`）读写，不进文档、不进撤销栈。

## 保存时序

`src/app/effects/persistence.ts` 在 `App` 首次挂载时 `installPersistence()` 订阅 store，只安装一次：

1. 监听到 `state.file` 引用变化 → `persist()`。
2. `persist()` 先 `dispatch({ type: 'ui/saveStatus', status: 'saving' })`，并重置 450ms 定时器（`SAVE_DEBOUNCE_MS`）。
3. 定时器到点后取值并 `saveFile`：成功置 `saved`，抛错置 `error` 并弹「本机保存失败，请导出 JSON 备份白板内容」。
4. 只改 `ui` 的命令（选中、切换工具、打开对话框）不改变 `state.file`，因此不触发保存。

因为写的是整个文件，拖动中的连续变更只会落在最后一次。代价是单次写入量等于全文档体积，图片多时写盘会变慢。

## 自动快照

同一订阅里另有一条独立链路：

- 用 `state.file.boards.map((b) => b.elements).join()` 生成元素标记，标记变化才进入 `scheduleSnapshot()`。
- 距上次自动备份不足 `AUTO_SNAPSHOT_CHECK_MS`（120s）时直接返回，不排定时器。
- 满足条件才排 `AUTO_SNAPSHOT_DELAY_MS`（20s）的定时器；20s 内再变动会重置定时器。
- 定时器触发时若当前白板没有元素，跳过；否则 `autoSnapshot(AUTO_SNAPSHOT_MAX)`。
- 自动快照名为「自动备份」，`auto: true`；手动版本名为用户输入或「手动版本」，`auto: false`。
- `snapshot/auto` 只裁剪自动版本：新的自动版本排最前，最多保留 15 条（`AUTO_SNAPSHOT_MAX`），手动版本全部保留并排在后面。

手动三条 action 在 `src/app/actions/snapshot.ts`：`saveVersion(name)`、`restoreSnapshot(id)`、`deleteSnapshot(id)`。恢复会覆盖元素与视口且**进撤销栈**；删除不进撤销栈。

## 导入

| 入口 | 校验 | 行为 |
| --- | --- | --- |
| 页面加载 | `parseFile` + `isValidElement` | 严格：`id`、`kind` 为字符串且 `x/y/w/h` 为有限数，否则丢弃该元素 |
| 导入 JSON | `normalizeImported` | 宽松：只要求 `id`、`kind` 为字符串且 `x/y` 为有限数，其余交给渲染层兜底 |
| 导入 Markdown | `markdownToElements` | 见下表 |

导入 JSON 的流程：读文本 → `JSON.parse` → 取 `data.elements`（若顶层就是数组则直接用）→ `normalizeImported` → 空数组则抛「文件中没有可用元素」→ 二次确认「导入将替换当前白板的全部内容，共 N 个元素」→ 一次性 dispatch `board/rename`（若文件带 `name`）、`board/replace`、清选区、退出编辑、关确认框 → 60ms 后 `fitToContent()`。

导入 Markdown 不走确认，直接追加：

1. `# 标题` → 文本元素，字号 `max(14, 28 - 级别 * 3)`、加粗。
2. `- [x] 任务` / `- [ ] 任务` → 卡片，`status` 置「待办」。
3. `- 列表项` 与普通段落 → 便签。
4. 元素纵向排列，步长 `(h || 80) + 24`，起点 `(40, 40)`。

## 导出总览

| 格式 | 入口 | 实现 |
| --- | --- | --- |
| SVG | `exportSVGFile` | `buildExportSVG` 序列化后下载 |
| PNG | `exportPNGFile` | SVG → `Image` → `canvas` → `toBlob` 下载 |
| PDF | `printBoard` | 新窗口写入 SVG，350ms 后调 `window.print()`，由打印对话框「另存为 PDF」 |
| JSON | `exportJSONFile` | 只导出元素数组 + 元信息，不是整份 `BoardsFile` |
| Markdown | `elementsToMarkdown` | 文本大纲，见下文 |

`exportBoard(kind)` 与 `exportPDF()` 在 `src/app/actions/io.ts`，共同前置步骤：

1. `commitEdit()`：先把正在编辑的文本落笔，避免导出丢字。
2. `exportTargets(state)` 按 `ui.exportScope` 取元素：`selection` 取选中元素，`content` 与 `view` 都取当前白板全部元素（`view` 的裁剪靠后面的 `bounds`，不筛元素）。
3. 空列表直接报错：「请先选择要导出的元素」或「白板还没有内容可以导出」。
4. `keepIds` 仅在 `selection` 范围下传入，用于裁剪 SVG 子树。
5. 背景：`ui.exportTransparent` 为真时传 `null`，否则 `#FFFFFF`。
6. 计算 `bounds`：`view` 范围用视口反变换算（`-x/zoom`、`-y/zoom`、`canvasSize/zoom`），其余用 `contentBounds(list)`，兜底 `800×600`。
7. 导出期间 `setBusy(...)`，结束 `setBusy(null)`；异常统一 toast「导出失败：…」。

## SVG 单一真源

`src/features/export/svg.ts` 的核心是 `buildExportSVG`，它不重新绘制任何元素：

```ts
const clone = content.cloneNode(true)          // 克隆画布真实 <g>
clone.querySelectorAll('[data-ui]').forEach(n => n.remove())   // 去掉选择框、参考线、角标
if (keepIds) 只保留 data-id 命中的子节点                          // 选区导出
clone.removeAttribute('transform')             // 平移缩放进 viewBox
```

输出结构：`<svg width=w*scale height=h*scale viewBox="x y w h">` + `<defs>`（镜头阴影等）+ 可选背景 `<rect>` + 克隆内容。`PAD = 40`，四个方向各留 40 单位空白。

因此新增元素只要在 `canvas/` 里实现渲染，导出就自动支持；反之，如果某元素渲染时没带 `data-id`，选区导出会漏掉它。

## PNG 光栅化

```ts
const svg = buildExportSVG(content, defs, bounds, scale, background, keepIds)
const url = `data:image/svg+xml;charset=utf-8,${encodeURIComponent(svg)}`
img.onload → canvas.width = (bounds.w + 80) * scale
ctx.drawImage(img, 0, 0, canvas.width, canvas.height)
canvas.toBlob(resolve, 'image/png')
```

- 缩放倍数来自 `ui.exportScale`（1x / 2x / 4x），直接作用在 canvas 尺寸上，不是 CSS 放大。
- 背景与 SVG 一致：透明模式不填 `fillRect`。
- 失败分支：图片加载失败抛「图片渲染失败」，`ctx` 取不到抛「无法创建导出画布」，`toBlob` 返回 `null` 抛「PNG 导出失败」。

## PDF 与打印

`printBoard` 没有 PDF 库，走浏览器打印：

1. `buildExportSVG(..., scale = 1, '#FFFFFF', keepIds)`。
2. `window.open('', '_blank')`，被拦截则抛「浏览器拦截了弹出窗口，请允许后重试」。
3. 文件名做安全处理：剔除 `<>:"/\|?*`，截断 60 字符，空则用 `OpenBoard`。
4. 写入带 `@page{margin:8mm}` 与 `svg{width:100%}` 的极简 HTML。
5. 350ms 后 `win.print()`。

## Markdown 映射

`src/features/markdown/convert.ts` 双向映射规则固定：

| 方向 | 规则 |
| --- | --- |
| 导出 · 导图 | 按 `parent` 建树，根节点从 `#` 起，层级最多 6 级；无根节点时取第一个节点当根 |
| 导出 · 便签与文本 | 按 y→x 排序，每条一个 `- 文本` |
| 导出 · 卡片 | `- [x] 文本 (状态)`，`done` 决定勾选 |
| 导入 · 标题 | `#{1,6}` → 文本元素，级别越高字号越小，加粗 |
| 导入 · 任务 | `- [ ]` / `- [x]` → 卡片，`status: '待办'` |
| 导入 · 列表与段落 | 其余非空行 → 便签 |

表格、图片、画笔、图形、容器不参与 Markdown 双向映射，导出时被忽略。
