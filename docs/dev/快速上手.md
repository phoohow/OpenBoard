# 快速上手

本文面向要改动 OpenBoard 源码的开发者：先用五分钟把项目跑起来，再弄清楚「改一处功能要看哪几层」，最后记住提交前必须过的三道门禁。阅读顺序建议是本文 → [架构总览](架构总览.md) → [目录结构与分层](目录结构与分层.md)。

## 环境要求

- Node.js 18 及以上（Vite 与 Vitest 的运行要求）。
- npm（仓库只提供 `package-lock` 生态下的 npm 脚本，未包含其他包管理器的锁文件）。
- 现代桌面浏览器（Chrome / Edge / Firefox 近期版本），建议窗口宽度不小于 1024px。

## 五个脚本

全部脚本定义在 `package.json`，没有额外的构建配置需要记忆。

| 命令 | 实际执行 | 用途 |
| --- | --- | --- |
| `npm install` | 安装依赖 | 首次拉取仓库后执行一次 |
| `npm run dev` | `vite --host 0.0.0.0` | 本地开发服务器，带热更新；同时允许局域网访问 |
| `npm run check` | `node scripts/check-layers.mjs` | 分层守卫：依赖方向、领域层禁 React、旧符号残留 |
| `npm test` | `vitest run` | 领域纯函数单测，一次跑完不进入 watch |
| `npm run build` | `tsc -b && vite build` | 先做 TypeScript 全量类型检查，再产出 `dist/` |
| `npm run preview` | `vite preview --host 0.0.0.0` | 预览构建产物 |

`check` 与 `test` 都只读源码，不产出文件；`build` 才是类型门禁，单独的 `vite build` 不会检查类型。

## 五分钟跑通

1. `npm install`。
2. `npm run dev`，打开终端里输出的地址（默认 `http://localhost:5173`）。
3. 在画布上按 `N` 画一块便签，双击输入文字，`Esc` 退出编辑。
4. 刷新页面确认内容还在——数据写入 localStorage，键为 `OpenBoard:v1`。
5. 另开一个终端跑 `npm run check && npm test`，确认基线是绿的再开始改。

## 改一处功能，该看哪几层

| 你想做的事 | 先改这里 | 通常还要动 |
| --- | --- | --- |
| 调整按钮文案或面板布局 | `src/ui/**` | 无（文案改动不需要动领域） |
| 改元素的字段或默认样式 | `src/model/types.ts`、`src/model/factories.ts` | `src/canvas/renderers/*`、`src/ui/layout/PropertyPanel.tsx` |
| 改交互行为（拖动、吸附、命中） | `src/app/interaction/pointer.ts`、`src/geometry/*` | 必要时补一条命令 |
| 新增一种文档变更 | `src/domain/commands/*` | `src/domain/reduce.ts` 挂载、`src/app/actions/*` 暴露 |
| 改保存策略或导出参数 | `src/app/config.ts`、`src/app/effects/persistence.ts` | `src/features/export/*` |
| 改键盘行为 | `src/app/interaction/keyboard.ts` | `docs/user/快捷键.md` 同步 |
| 加模板、图形或素材 | `src/features/templates/library.ts`、`src/model/constants.ts`、`src/features/assets/library.ts` | 对应面板的渲染分支 |

判断依据是依赖方向：`model ← geometry ← domain ← features ← app ← App.tsx`，`ui` / `canvas` 只向下依赖。改上层不会影响下层，但改下层要检查所有上层引用点。

## 提交前的三道门禁

```bash
npm run check   # 依赖方向与旧符号
npm test        # 领域单测（当前 8 个文件 55 条用例）
npm run build   # TypeScript 全量类型检查 + 产物构建
```

三条都通过才算完成。如果改动涉及界面文案或数量类事实（图形种类、模板数量、快照保留条数），必须同步更新 `docs/user` 与 `docs/dev` 的对应篇目，具体清单见 [文档中心](../README.md)。
