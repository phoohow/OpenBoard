# 代码规范

规范的目标只有一个：让下一个人（或下一次的自己）能在五分钟内定位改动点。本文按「命名 → 分层 → 领域 → 命令 → React → 样式 → 注释 → 提交」组织，全部规则都能在现有代码里找到对应样例。

## 命名与文件组织

| 对象 | 规则 | 样例 |
| --- | --- | --- |
| 组件文件 | PascalCase，一个文件一个主组件 | `TopBar.tsx`、`CanvasStage.tsx` |
| 非组件模块 | camelCase | `selectors.ts`、`hitTest.ts`、`persistence.ts` |
| 组件 | PascalCase，`*View` 后缀用于 memo 前的实现体 | `TopBarView` 被 `memo` 包成 `TopBar` |
| 函数 / 变量 | camelCase，动词开头 | `addSticky`、`fitToContent`、`orderedElements` |
| 类型 / 接口 | PascalCase，不加 `I` 前缀 | `EditorState`、`BoardElement`、`CommandMeta` |
| 常量 | UPPER_SNAKE | `HISTORY_LIMIT`、`SAVE_DEBOUNCE_MS`、`GRID` |
| 命令类型串 | `域/动词`，小写驼峰动词 | `elements/patch`、`board/duplicate`、`mindmap/addNode` |
| 测试文件 | 与被测文件同名 + `.test.ts`，目录镜像 | `test/domain/commands/table.test.ts` |

目录按层划分而不是按功能划分：`model` / `geometry` / `domain` / `features` / `app` / `ui` / `canvas`。同一功能的文件分散在多层是正常的（例如导图 = `domain/mindmap/*` + `domain/commands/mindmap.ts` + `app/actions/mindmap.ts` + `ui/panels/MindmapPanel.tsx` + `canvas/renderers/mindnode.tsx`）。

## 分层与导入

- 依赖方向 `model ← geometry ← domain ← features ← app ← App.tsx`；`ui` / `canvas` 只向下依赖且互不依赖。规则由 `scripts/check-layers.mjs` 强制。
- 跨层用 `@/` 别名，同层用相对路径。所有导入按文件精确指向实现文件，不设 `index.ts` barrel 出口。
- 类型导入写 `import type`。`isolatedModules` 开启后，混入值导入会在构建时报错。
- 不在 `domain` 里 `import react`，不在 `features` 里引用 `app`。需要 React 的能力说明它属于 `ui` 或 `app`。
- 只在文件内部使用的助手不导出：多余的 `export` 就是多余的对外接口，会把内部分支变成别人可用的入口（`geometry/box.ts` 的 `isInsideFrame`、`domain/document.ts` 的 `normalize*` 都是范例）。入口函数已经够用时，内部步骤保持 `const`。
- 死导入与未使用局部变量由 `tsconfig` 的 `noUnusedLocals` / `noUnusedParameters` 拦截，`npm run build` 直接失败。

## 领域代码

- **纯函数**：`(input, cmd) => output | null`，不改入参，不读时钟（`Date.now()` 只在 `patchActive` 与 action 里打点），不碰 `localStorage` / `document`。
- **未命中返回 `null`**：每个 reducer 只认领自己的命令，`default` 分支一律 `return null`。
- **内容未变返回原引用**：这是跳过重渲染与历史记录的关键。`rewrite` 辅助函数就是为此存在。
- **派生数据不进 state**：能从 `file` + `ui` 算出来的（有序元素、选中项、票数、演示序列）都放 `selectors.ts`，用 `useMemo` 或模块级缓存。
- **归一化集中在入口**：外部数据只经 `parseFile` / `normalizeImported`，不在各处零散兜底。
- **默认值只写一处**：元素默认尺寸 / 文案 / 配色由 `baseElement` 给出，共用调色常量进 `model/constants.ts`（`DEFAULT_FILL`、`DEFAULT_STROKE`、`DEFAULT_INK`）。`createElement` 等调用方只覆盖与工厂不同的字段，不再重复赋一遍工厂已经给好的值；默认笔宽这类初始值也从预设表（`penPresets.pen.width`）取，而不是重抄一个数。

## 命令优先

任何文档变更都必须新增或复用一条命令，不允许直接改 `state.file`：

| 不要 | 要 |
| --- | --- |
| 组件里 `setElements([...])` | `actions.elements.*` 或 `dispatch({ type: 'elements/add', ... })` |
| action 里手工拼 `{ ...file, boards }` | 定义命令，让 reducer 拼 |
| 用 `history: false` 图省事 | 只有视口、设置、评论、路线、快照裁剪、拖拽中间态才关历史 |

一次交互产生多条变更时用 `dispatch(cmd1, cmd2, ...)` 一次提交，只触发一次通知与一次渲染。

## React

- **组件只读不写**：业务状态全部来自 `useEditor()` 或 props；组件内部 `useState` 只允许存纯瞬时的 UI 值（例如输入框草稿、菜单展开、快捷键录入的本地缓冲）。
- **窄 props**：向下传 `doc` / `ui` / `derived` 里真正需要的字段，不要把整个 `state` 传下去。`CanvasStage` 的 `CanvasScene` / `CanvasUi` 是范例。
- **memo 到位**：重渲染热点（`CanvasStage`、`TopBar`、`Sidebar`、`PropertyPanel`）用 `memo`；`App.tsx` 用 `useMemo` 稳定 `scene`、`handlers`、`editor`、`overlay`。
- **actions 引用恒定**：action 是模块级函数，不写在组件里、不用 `useCallback` 包，直接作为 props 传。
- **副作用集中在两处**：全局监听的安装在 `app/effects/lifecycle.ts`，持久化在 `app/effects/persistence.ts`。组件里只在确实需要时用 `useEffect`（例如顶层菜单的点击外部关闭）。
- **列表 key 用稳定 id**：元素用 `el.id`，不要用数组下标。

## 样式

- 样式文件在 `src/styles/`，按 `index.css` 的 `@import` 顺序生效：`tokens → layout → interaction → canvas → panels → dialogs → feedback → dataViews`。新增样式放进对应文件，不要新建零散 css。
- 颜色、间距、圆角优先用 `tokens.css` 里的 CSS 变量。
- 类名用 kebab-case 语义名（`canvas-wrap`、`tool-rail`、`present-bar`），不用 BEM 与工具类前缀。
- 内联 `style` 只用于**运行时计算值**：视口变换、草稿尺寸、浮层坐标、动态进度。静态样式一律进 css。
- 不用 CSS-in-JS，不引入 UI 组件库；图标统一来自 `lucide-react`。

## 注释

- 每个文件顶部有一句块注释，说明「这个文件负责什么」。样例：`/** 纯 reduce：(state, command) => state。唯一写入口的实现，不含 IO 与 React。 */`
- 注释写「为什么」，不写「做了什么」。例如「容器始终渲染在最底层，避免遮挡内部内容」。
- 关键取舍要留痕：`patchActive` 里「认领了命令但内容没变：保持原引用，不刷新时间戳」这类注释比函数名更有价值。
- 全中文注释，标点用中文标点；不写 emoji，不写作者与日期。
- 需要压制 lint 的地方写明原因，例如 lifecycle 里计时器 effect 的 `react-hooks/exhaustive-deps` 注释。

## 提交前

```bash
npm run check   # 分层与旧符号
npm test        # 领域单测
npm run build   # 类型 + 产物
```

同时检查：

- 改的是下层（`model` / `geometry`）时，是否已排查所有上层引用点。
- 新增命令是否补了 reducer 注册、action、测试与文章中的命令表。
- 界面文案变化是否同步到 `docs/user` 对应篇目。
- 数量与阈值变化（图形数、模板数、快照条数、缩放范围）是否同步到用户文档与开发者文档。
