# 架构总览

本文回答三个问题：这套代码由什么构成、为什么这样分层、一次用户操作从点击到落盘经过了哪些环节。结论先行，细节在后续各篇展开。

## 技术栈

| 维度 | 选择 | 说明 |
| --- | --- | --- |
| 视图框架 | React 19 | 函数组件 + Hooks，严格模式关闭副作用 |
| 语言 | TypeScript 5.9（`strict`） | `tsconfig.json` 开启 `strict`、`noEmit`，`@/*` 映射到 `src/*` |
| 构建 | Vite | 开发服务器 `--host 0.0.0.0`，测试走 `vitest run` |
| 渲染 | 原生 SVG | 画布、元素、参考线、选择框全部是 SVG 节点，没有 Canvas 2D 与第三方图形库 |
| 状态 | 自建 store | `useSyncExternalStore` + 纯函数 `reduce`，不引入 Redux / Zustand |
| 持久化 | localStorage | 键 `OpenBoard:v1` 存文档，`OpenBoard:favorites` 存收藏 |
| 图标 | lucide-react | 仅用于界面按钮，不参与画布渲染 |
| 测试 | Vitest | 只测 `domain` 纯函数，`environment: 'node'`，不含 DOM |

## 五条设计原则

- **单一写入口**：任何文档变更都必须是一条命令，经 `dispatch` 进入 `reduce`。`scripts/check-layers.mjs` 会拦截 `setElements(` 这类绕过写入口的旧符号。UI 组件不持有业务状态，只读派生数据、调 action。
- **领域是纯函数**：`domain` 不依赖 React，`reduce(file, doc, state, cmd)` 是同步纯函数：相同输入必然得到相同输出，不读时钟、不读 DOM、不写存储。时间戳（`updatedAt`）由 `reduce` 内部统一打点，副作用全部收在 `app`。
- **单向依赖**：`model ← geometry ← domain ← features ← app ← App.tsx`，`ui` / `canvas` 只允许向下依赖。上层可以换实现，下层不受影响；`features`（导出、存储、模板、素材、Markdown）能独立被 `app` 与 `ui` 复用。
- **SVG 是单一渲染源**：屏幕上看到的内容和导出的内容来自同一棵 DOM 子树：`buildExportSVG` 直接克隆画布里的 `<g>`，按 `data-ui` 标记剔除交互层。因此不存在「画布一套、导出一套」的漂移。
- **本地优先**：没有账号、接口与服务端。打开即用，内容只存在当前浏览器的 localStorage，导出 JSON 是唯一的跨设备手段。

## 分层图

```
src/App.tsx                装配：把 doc/ui/derived/actions 分发给视图
   ├── src/ui/**           界面：顶栏、侧栏、面板、对话框（纯展示 + 调 action）
   ├── src/canvas/**       画布：SVG 场景、元素渲染器、覆盖层、文本编辑浮层
   ├── src/app/**          应用：store、actions、effects、interaction、hooks
   ├── src/features/**     能力：导出、存储、模板、素材、Markdown（可脱离 React）
   ├── src/domain/**       领域：文档模型、命令、reduce、历史、选择器（纯函数）
   ├── src/geometry/**     几何：包围盒、文本布局、形状轮廓、连接线、命中
   ├── src/model/**        模型：类型、常量、工厂、守卫（无依赖）
   └── src/styles/**       样式：按 tokens → layout → interaction → canvas → panels → dialogs → feedback → dataViews 顺序引入

依赖方向：model ← geometry ← domain ← features ← app ← App.tsx（ui / canvas 只向下依赖）
```

箭头方向即依赖方向。`ui` 与 `canvas` 处在同一层，可以互相不依赖地并行演进；二者都不允许被 `domain` 反向引用。

## 一次交互的完整数据流

以「按 `N` 在画布上点一下创建便签」为例：

1. `src/app/interaction/pointer.ts` 收到 `pointerdown`，换算成画布坐标，算出落点与默认尺寸。
2. 调用 `actions.elements.addSticky(point)`——action 内部用 `model/factories.ts` 的 `baseElement('sticky', x, y)` 造出元素，再 `dispatch({ type: 'elements/add', elements: [el] })`。
3. `src/app/store.ts` 的 `dispatch` 依次把命令喂给 `domain/reduce.ts`：先处理 `history/*` 与 `ui/*`，其余交给 `reduceDoc`。`reduceDoc` 按分片顺序尝试 `reduceBoards` → `reduceSettings` → `reduceBoardContent` → `reduceElements` → `reduceArrange` → `reduceGroup` → `reduceTable` → `reduceMindmap` → `reduceCollab` → `reduceSnapshot` → `reduceView`，第一个返回非 `null` 的结果即为止。
4. `reduceDoc` 通过 `patchActive` 写回 `activeBoard`（内容未变时保持原引用、不刷新 `updatedAt`），再用 `commitFile` 把变更前的 `elements` 压入 `past`；带 `history: false` 的命令只换文件、不进撤销栈。
5. `dispatch` 只 `notify` 一次；`useEditor()` 通过 `useSyncExternalStore` 取到新 `state`，用记忆化选择器派生 `doc / ui / derived`。
6. `App.tsx` 把 `derived.ordered` 传给 `CanvasStage`；`canvas/renderers/render.tsx` 的 `renderElement` 按 `kind` 分发到具体渲染器，画到屏幕上。
7. 同时 `src/app/effects/persistence.ts` 观察到 `state.file` 变化，450ms 防抖后写入 localStorage；保存成功把 `saveStatus` 置为 `saved`，失败则置 `error` 并弹提示。

整个过程里没有组件内部的业务 state，视图永远是被动渲染结果。

## 渲染概要

- `CanvasStage` 只接收 `scene` / `ui` / `refs` / `handlers` 四个窄切片，外层 `<g transform="translate(x y) scale(zoom)">` 承担无限画布。
- 图层顺序固定为：导图连线 → 元素（容器强制最底层）→ 参考线 → 拖拽草稿 → 角标 → 选择框。
- 元素渲染是纯函数：输入 `BoardElement`，输出 SVG；`wrapNode` 统一处理旋转、透明度与 `data-id`。
- 文本度量不依赖 DOM，用 `geometry/text.ts` 的字符宽度估算做换行与自动撑高，保证导出与服务端环境可复现。

细节见 [渲染与几何](渲染与几何.md)。

## 持久化概要

- 文档整体存一份：`BoardsFile` 内含全部白板、当前 `activeId` 与全局 `settings`。
- 保存是「整文件覆盖 + 防抖」，不做增量；450ms 内的连续拖动只会写一次。
- 自动快照由独立 effect 驱动：每 120s 检查一次元素标记，变化后再等 20s 落一条自动备份，自动备份最多保留 15 条，手动版本不计入上限。
- 导出以 SVG 为真源：PNG 由 SVG 光栅化，PDF 走打印窗口，Markdown 由元素文本按固定规则映射。

细节见 [持久化与导出](持久化与导出.md)。

## 关键取舍

| 取舍 | 选择 | 代价 |
| --- | --- | --- |
| 状态管理 | 自建 store + 纯函数 reduce | 没有中间件与调试工具，命令表需要自己维护 |
| 渲染方式 | 全量 SVG | 元素极多时 DOM 节点数偏大，靠 `memo` 与窄切片控制重渲染 |
| 历史记录 | 只记录 `elements` 数组 | 视口变化不占撤销栈，但重命名、评论等也不可撤销 |
| 协作 | 不做实时协作 | 能力边界清晰，但数据共享只能靠 JSON 导出 |
| 导出 | 复用屏幕上的 SVG | 依赖 DOM，导出必须在浏览器里执行；换来与画布零差异 |
| 文本 | 自己估算字宽 | 与真实字体有偏差，换来布局可在纯 JS 环境计算 |
