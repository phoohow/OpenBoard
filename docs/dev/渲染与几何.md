# 渲染与几何

画布是纯 SVG，没有 Canvas 2D、没有第三方图形库。本文先给渲染骨架与图层顺序，再给文本、形状、连接线、导图四类几何的算法要点，最后说明交互覆盖层与状态差异。

## 渲染骨架

`src/canvas/CanvasStage.tsx` 是唯一入口，接收四组窄切片：

| prop | 内容 |
| --- | --- |
| `scene` | `view`、`grid`、`background`、`cursor`、`elements`、`selected`、`editingId`、`guides`、`draft`、`comments` |
| `ui` | `presenting`、`laserOn`、`laserPoint`、`reactions`、`voteMode`、`tool` |
| `refs` | `wrap`（外层 div）、`svg`、`content`（画布 `<g>`）、`defs` |
| `handlers` | `onPointerDown/Move/Up`、`onDoubleClick`、`onLaserMove` |

结构固定为：

```jsx
<div class="canvas-wrap bg-{mode}">        // 背景网格用 CSS background 画，不占 DOM
  <svg class="canvas">
    <defs>… ob-sticky-shadow …</defs>
    <g ref={content} transform="translate(view.x view.y) scale(view.zoom)">
      …
    </g>
  </svg>
  {激光笔圆点}{互动表情}{文本编辑浮层}{画布浮层}
</div>
```

要点：

- 无限画布只靠这一层 `transform` 实现，元素坐标始终是画布坐标，不随缩放改写。
- 背景网格用 `backgroundSize = grid * zoom`、`backgroundPosition = view.x / view.y` 同步平移缩放；`plain` 模式不设内联样式。
- 组件用 `memo` 包住。`App.tsx` 用 `useMemo` 稳定 `scene` / `handlers`，避免画布在无关状态变化时重绘。
- 激光笔圆点与互动表情是 DOM 浮层（`div` / `span`），不在 SVG 里，所以导出时天然被排除。

## 图层顺序

`content` 内部的顺序即绘制顺序，从下到上：

1. `MindLinkLines`：所有导图父子连线（`mindLinks`）。
2. 元素：`orderedElements` 先把容器提到最前（最底层），再按数组原序绘制；`visible === false` 的元素直接过滤。
3. `Guides`：智能参考线。
4. `Draft`：框选矩形与连线草稿。
5. `Badges`：评论角标与投票角标。
6. `Selection`：选择框、缩放手柄、多选包围框。

容器永远在最底层是硬规则：否则容器的填充会盖住里面的便签与图形。

## 元素渲染分发

`src/canvas/renderers/render.tsx` 的 `renderElement(el, ctx)` 是一个 `switch`：

| kind | 渲染器 | 文件 |
| --- | --- | --- |
| `mindnode` | `MindNodeShape` | `renderers/mindnode.tsx` |
| `table` | `TableShape` | `renderers/table.tsx` |
| `card` | `CardShape` | `renderers/card.tsx` |
| `sticky` / `shape` / `text` / `draw` / `frame` / `image` / `connector` | 对应 `*Element` | `renderers/basic.tsx` |

`wrapNode(el, inner)` 统一包一层 `<g data-id={el.id} transform={rotationTransform(el)} opacity={...}>`：

- `rotationTransform` 由 `geometry/box.ts` 计算，绕元素中心旋转，无旋转时返回 `undefined`。
- `data-id` 是命中与导出过滤的锚点：`cloneContent` 依靠它按选中集合裁剪。
- 有旋转时才把 `opacity` 提到包裹层，无旋转时由内部节点各自带 `opacity`，避免重复合成。

各渲染器的关键细节：

| 元素 | 实现要点 |
| --- | --- |
| 便签 | `rect` 圆角 12 + `filter="url(#ob-sticky-shadow)"` 投影，正文用 `TextNode` |
| 图形 | 先试 `isElliptical`（椭圆类）→ `shapePath`（path）→ `shapePolygon`（polygon）→ 兜底 `rect`；`round` 用 `rx=16`；`shapeInnerLines` 画数据库、类图等内部辅助线 |
| 文本 | 填充色非透明时先画底 `rect`，再无内边距排版 |
| 画笔 | `pointsToPath` 转成平滑路径，`translate(x y)` 后绘制，圆头圆角 |
| 容器 | 描边固定虚线 `8 6`；名称画在 `y - 10`，不占内部空间 |
| 图片 | 有 `src` 画 `image`，否则画虚线占位框 |
| 连接线 | 几何由 `connectorGeometry` 算出；箭头大小 `max(9, strokeWidth * 3.4)`；有文字时在标签点画白底描边圆角框 |

## 文本布局

`src/geometry/text.ts` 不依赖 DOM，全部用字符宽度估算：

| 函数 | 作用 |
| --- | --- |
| `charWidth(code, fontSize, narrowRatio)` | 码位 > `0x2e7f` 视为宽字符按 `fontSize` 计，其余按 `0.55 * fontSize` |
| `estimateWidth(text, fontSize, ratio)` | 单行估算宽度，用于角标、卡片与节点排布 |
| `clipText(text, fontSize, maxWidth)` | 超宽截断并补省略号 |
| `wrapText(text, maxWidth, fontSize)` | 先按 `\n` 分段；中文逐字断行，英文按空格断词 |
| `layoutText(el)` | 返回 `{ lines, lineHeight, x, anchor, firstY }`：行高 `fontSize * 1.35`，非文本元素左右内边距 16，垂直按盒子居中 |
| `autoHeight(el)` | 便签 = 行数 × 行高 + 32（最小 96）；文本 = 行数 × 行高 + 12（最小 `fontSize * 1.6`） |

`TextNode` 把 `lines` 渲染成多个 `<tspan>`，`x` 与 `textAnchor` 由 `align` 决定（left/start、center/middle、right/end）。正在编辑的元素会带 `editing-text` 类，用于隐藏原文、把位置让给输入框。

## 形状几何

`src/geometry/shapes.ts` 覆盖 52 种图形，三条出口按优先级调用：

- `shapePath(el)`：需要曲线或非凸轮廓的图形（心形、云、对话气泡、文档、UML 组件等）返回 SVG `d`。
- `shapePolygon(el)`：纯多边形（三角、菱形、五边形、六边形、星形、箭头等）返回 `points` 字符串。
- `shapeInnerLines(el)`：数据库双层线、类图分区线、包图折角等内部辅助线，返回线段数组。
- `isElliptical(kind)`：`circle` / `ellipse` / `erAttribute` 走 `ellipse`。

渲染器按 `isElliptical → shapePath → shapePolygon → rect` 的顺序取第一个可用结果，新增图形只要在这三个函数里补分支即可。

## 连接线

`src/geometry/connector.ts`：

1. `connectorEnds(el, elements)` 解析两端：`from` 与 `to` 必须同时存在且能命中元素，否则返回 `null`，该连接线不渲染。
2. `edgeAnchor(el, target)` 把目标中心投影到元素边上，得到一个贴边锚点（椭圆按外接矩形近似）。
3. 按 `connectorStyle` 生成路径：`straight` 直连、`elbow` 沿水平/垂直中轴走三段折线、`curve` 用三次贝塞尔（控制点按水平或垂直主导方向取 `min(120, 长度 * 0.45)`）。
4. `arrowHead(tip, dir, size)` 调用 `arrowPolygon` 生成箭头三角形（张角 0.42），`arrowStart` / `arrowEnd` 各自控制。
5. 返回 `{ d, start, end, startDir, endDir, label }`，`label` 是路径中点（曲线按控制点加权求值），用于放文字。

端点只在渲染与命中时实时计算，不写回元素，所以移动节点后连接线自动跟随。

## 导图布局

`src/domain/mindmap/layout.ts` 的常量决定观感：

```
MAX_W 232  MIN_W 112  PAD_X 18  PAD_Y 12  H_GAP 80  V_GAP 26  V_LEVEL_GAP 74
```

- `mindNodeSize(el)`：先按单行文字估宽并夹在 `112~232`，再用 `layoutText` 试探换行，取最宽行作为最终宽度；高度 = `max(fontSize * 2.3, 行数 × 行高 + 24)`。
- `layoutMindTree(elements, rootId)` 返回 `id → Point`：
  - `right` / `left`：根节点保持原位，子节点纵向居中铺开，横向间隔 `H_GAP`，同层间隔 `V_GAP`。
  - `both`：按子节点奇偶分到左右两侧，各自居中。
  - `topdown`：子节点横向铺开、纵向间隔 `V_LEVEL_GAP`。
- `normalizeMindmaps(elements)`：先统一尺寸与 `rootId`，再对每棵根节点做一次布局。无导图节点时返回原数组引用，有变化时返回新数组。
- `mindLinks(elements)`：跳过被折叠的父节点与不可见分支，按 `topdown` 或左右方向选择锚点，输出三次贝塞尔 `d` 与颜色（取子节点描边，回落 `DEFAULT_STROKE` 即 `#B9A8EA`）。
- `mindLevelOf(elements, id)` 返回层级（根为 0），用于新节点的字号与配色档位。

折叠只影响可见性，不改数据结构：`visibleKids` 遇到 `collapsed` 就返回空数组，布局与连线随之收缩。

## 覆盖层与编辑浮层

| 组件 | 职责 |
| --- | --- |
| `overlays/Selection.tsx` | 单选画 1px 内缩选框，并在右下角画一个 10×10 手柄（仅 `select` 工具、非连接线）；多选额外画虚线外框；全部用 `vectorEffect="non-scaling-stroke"` 保持屏幕线宽 |
| `overlays/Guides.tsx` | 吸附时出现的水平/垂直参考线 |
| `overlays/Draft.tsx` | 框选矩形与「从某元素拉线」的预览；演示态下不画 |
| `overlays/Badge.tsx` | 未解决评论取首字画橙色圆标；投票模式下画紫色票数标；演示态下不渲染 |
| `EditingOverlay.tsx` | 计算编辑框在屏幕上的位置（用 `view` 反变换），把输入框叠在元素上方 |
| `TextEditorOverlay.tsx` | 真正的输入框；表格里 `Tab` 跳下一格、`Enter` 下一行；导图里 `Enter` 提交并加同级、`Tab` 提交并加子节点；失焦即提交 |

## 状态差异

同一套渲染函数在不同状态下表现不同，改动时要同时考虑：

| 状态 | 差异 |
| --- | --- |
| `locked` | 命中跳过（`hitTest` 默认 `skipLocked = true`），不显示缩放手柄 |
| `visible === false` | `orderedElements` 过滤，完全不渲染，但仍在数据里 |
| `presenting` | 选择框、草稿、角标都不渲染；元素本身照常绘制，聚焦靠视口变换 |
| `voteMode` | 便签与卡片显示票数角标 |
| `editingId` | 该元素正文加 `editing-text` 类（隐藏原文），编辑框叠加在上方 |
