# 状态与命令

OpenBoard 的所有变更都汇成一条命令，经 `dispatch` 进入纯函数 `reduce`。本文给出状态结构、store 的三个 API、完整命令表、历史栈规则、action 的组织方式，以及新增一条命令的五步流程。

## EditorState

定义在 `src/domain/state.ts`，是 `dispatch` 操作的对象，也是 `useSyncExternalStore` 订阅的值。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `file` | `BoardsFile` | 持久化根：全部白板、`activeId`、全局 `settings` |
| `past` | `BoardElement[][]` | 撤销栈，元素快照数组 |
| `future` | `BoardElement[][]` | 重做栈 |
| `ui` | `UiState` | 与文档无关的瞬时界面状态 |
| `toasts` | `ToastItem[]` | 轻提示队列 |
| `saveStatus` | `'saved' \| 'saving' \| 'error'` | 顶栏保存状态 |
| `busy` | `string \| null` | 长任务文案（导出等） |

`DocState`（`src/domain/history.ts`）是 `EditorState` 的文档子集：`{ file, past, future }`。`reduceDoc` 只在 `DocState` 上工作，`reduce` 再把结果合并回 `EditorState`。

## store 的三个 API

`src/app/store.ts` 是一个模块级单例，不依赖 React。

| API | 签名 | 用法 |
| --- | --- | --- |
| `getState` | `() => EditorState` | 供 `useSyncExternalStore` 取快照；引用不变即视为未变化 |
| `subscribe` | `(listener) => () => void` | 注册监听，返回退订函数 |
| `dispatch` | `(...cmds: Command[]) => void` | 唯一写入口；可一次传多条 |

核心实现只有十几行：

```ts
let state: EditorState = createEditorState(loadFile())

export const dispatch = (...cmds: Command[]): void => {
  let next = state
  for (const cmd of cmds) next = reduce(next, cmd)
  if (next === state) return
  state = next
  notify()
}
```

- 一次传多条时按顺序 `reduce`，全部处理完只 `notify` 一次——批量操作（例如「改名 + 替换内容 + 适配视图」）只触发一次渲染。
- `reduce` 返回同一个引用时不通知，避免无意义重渲染。
- 没有异步、没有订阅外部事件；持久化由 `src/app/effects/persistence.ts` 订阅 store 完成。

## 命令联合类型

`src/domain/commands/command.ts` 定义三层联合：

```ts
export type Command = DocCommand | UiCommand | StateCommand | HistoryCommand
```

| 联合 | 包含 | 走向 |
| --- | --- | --- |
| `DocCommand` | `BoardFileCommand` / `BoardContentCommand` / `ElementCommand` / `ArrangeCommand` / `GroupCommand` / `TableCommand` / `MindmapCommand` / `CollabCommand` / `SnapshotCommand` / `ViewCommand` / `SettingsCommand` | `reduceDoc` |
| `UiCommand` | 每个 `UiState` 字段一条：`ui/<字段名>` | `reduceUi` |
| `StateCommand` | `ui/toast`、`ui/toastDismiss`、`ui/saveStatus`、`ui/busy` | `reduceStateCommand` |
| `HistoryCommand` | `history/undo`、`history/redo`、`history/push` | `undo` / `redo` / `pushHistory` |

每条文档命令都带可选的 `CommandMeta`：

```ts
export interface CommandMeta { history?: boolean }
```

`history` 缺省为 `true`（进撤销栈）。传 `false` 表示「只改文档、不占撤销栈」，当前用于：`board/rename`、`settings/patch`、`view/set`、`comment/*`、`route/*`、`snapshot/delete`、`snapshot/auto`，以及指针状态机在拖拽中批量更新位置的 `elements/set`。

## reduce 契约

`src/domain/reduce.ts`：

1. `history/*` 先处理，直接返回新的 `{ past, future }` 切片。
2. `ui/*` 走 `reduceUi`，不匹配再走 `reduceStateCommand`。
3. 其余交给 `reduceDoc`：
   - 先试文件级 reducer：`reduceBoards`、`reduceSettings`。
   - 再对 `activeId` 指向的白板依次试 `boardReducers`，第一个返回非 `null` 的生效。
   - 认领了命令但内容没变（返回原白板引用）时，不刷新 `updatedAt`、不记历史。
   - `touchesUpdatedAt(type)` 对 `view/set` 返回 `false`，即移动视口不改白板修改时间。
   - `resetsHistory(type)` 对 `board/create|select|duplicate|delete` 返回 `true`，这些命令直接清空 `past` 与 `future`。
4. 其余命令走 `commitFile`：`history !== false` 时把**变更前**的 `elements` 压入 `past`，并清空 `future`。

写 reducer 的三条硬要求：不读时钟以外的外部状态（`Date.now()` 由 `patchActive` 统一打点）、不改入参、内容未变必须返回原引用。

## 文档命令表

### 白板与文件

| 命令 | 载荷 | 行为 | 历史 |
| --- | --- | --- | --- |
| `board/rename` | `id`、`name` | 改名，同名返回 `null` | 否 |
| `board/create` | `board` | 追加白板并切为当前 | 清空 |
| `board/select` | `id` | 切换当前白板，不存在或已是当前返回 `null` | 清空 |
| `board/duplicate` | `id`、`newId` | 深拷贝，重映射 `id/from/to/parent/rootId/groupId`，名字追加「副本」，复制评论与路线、不复制快照 | 清空 |
| `board/delete` | `id` | 删除；删空后补一块「未命名白板」 | 清空 |
| `board/clear` | 无 | 清空当前白板元素 | 是 |
| `board/replace` | `elements`、`view?` | 整体替换元素，可选替换视口 | 是 |
| `view/set` | `view` | 设置视口，坐标与缩放相同返回 `null` | 否 |
| `settings/patch` | `patch` | 合并全局设置，始终与 `defaultSettings()` 兜底合并 | 否 |

### 元素

| 命令 | 载荷 | 行为 |
| --- | --- | --- |
| `elements/set` | `elements` | 整体替换元素数组 |
| `elements/add` | `elements` | 追加，空数组返回原白板 |
| `elements/patch` | `ids`、`patch`、`skipLocked?` | 批量打补丁；`skipLocked` 时跳过锁定元素 |
| `elements/remove` | `ids`、`cascadeMind?`、`dropConnectors?` | 删元素；默认连带导图子树与挂在被删元素上的连接线 |
| `elements/reorder` | `ids`、`front \| back` | 置顶 / 置底 |
| `elements/moveLayer` | `ids`、`up \| down` | 上移 / 下移一层 |
| `elements/rotate` | `ids`、`deg` | 旋转并归一化到 -180~180，跳过锁定元素 |
| `elements/replaceText` | `id`、`value`、`cell?` | 落笔文本；表格写单元格；便签/文本按需自动撑高；随后重新归一化导图 |
| `elements/align` | `ids`、`kind` | 六向对齐，至少 2 个未锁定非连接线目标 |
| `elements/distribute` | `ids`、`kind` | 水平 / 垂直等距分布，至少 3 个目标 |
| `elements/group` | `ids`、`groupId` | 成组；`groupId: null` 即解组；锁定元素不参与成组 |
| `elements/table` | `id`、`action` | `row+ / row- / col+ / col- / header` |

### 界面命令

`UiCommand` 由类型映射生成，命令名即字段名，例如 `ui/selection`、`ui/tool`、`ui/dialog`、`ui/presenting`、`ui/exportScale`。`UiState` 的词表见 `src/domain/ui.ts`，分六组：

| 组 | 字段 |
| --- | --- |
| 工具与绘制参数 | `tool`、`shapeKind`、`shapeFill`、`stickyColor`、`penColor`、`penWidth`、`penMode` |
| 选择与编辑 | `selection`、`editing`、`selectAll` |
| 面板与对话框 | `dialog`、`confirm`、`panelOpen`、`commentOpen`、`search` |
| 画布瞬时值 | `spaceDown`、`canvasSize`、`draft`、`guides`、`clipboard`、`stickyIndex` |
| 演示 | `presenting`、`presentStep`、`presentMode`、`laserOn`、`laserPoint`、`timerTotal`、`timerLeft`、`timerRunning`、`reactions`、`voteMode` |
| 导出参数 | `exportScope`、`exportScale`、`exportTransparent` |

`reduceUi` 用 `Object.is` 判等，同值直接返回 `null`。

## 历史栈规则

- 上限 `HISTORY_LIMIT = 120`，超出后从最旧一端截断。
- 只记录 `elements`，不记录视口、设置、评论、路线、快照、白板名。
- 新命令入栈时清空 `future`（重做链断裂）。
- `board/create|select|duplicate|delete` 清空双向栈：换板之后旧历史不再适用。
- 拖拽类交互在开始时用 `history/push` 记一次快照，过程中用 `history: false` 的 `elements/set`/`elements/patch` 连续更新，这样一次拖拽只产生一条撤销记录。

## action 的组织方式

`src/app/actions/` 按领域分十个模块，`src/app/actions.ts` 汇成常量对象：

```ts
export const actions = { board, collab, elements, io, mindmap, present, snapshot, text, ui, viewport }
```

- 每个 action 都是模块级函数，无闭包、无内部状态，所以 `actions` 引用恒定，可以直接作为 props 传下去配合 `memo`。
- action 负责「读当前状态 → 算载荷 → `dispatch`」，不负责渲染。需要多步变更时把命令作为多个实参一次提交。
- `actions.ts` 只聚合分组对象，不重复导出单个 action；需要具体函数时从 `actions/` 下对应模块导入（如 `./actions/ui`、`./actions/viewport`）。
- 破坏性操作用 `actions.ui.confirm(...)` 弹出二次确认，确认回调里再 `dispatch`。

## useEditor 门面

`src/app/hooks/useEditor.ts` 是视图层唯一入口：

| 返回字段 | 内容 |
| --- | --- |
| `state` | 原始 `EditorState`（`saveStatus`、`toasts`、`busy` 从这取） |
| `doc` | `EditorDoc`：`board`、`elements`、`view`、`settings`、`comments`、`route`、`snapshots` |
| `ui` | `UiState` |
| `derived` | 下面 14 项派生值 |
| `actions` | 恒定的 action 对象 |

`derived` 由 `src/domain/selectors.ts` 的记忆化函数计算：

| 字段 | 来源 |
| --- | --- |
| `selection` | `ui.selection` |
| `selected` | `selectedElements(state)` |
| `ordered` | `orderedElements(currentElements(state))`，按 y→x 排序；渲染时容器再被提到最底层 |
| `boards` | `boardsMeta(state)`：id、名称、更新时间、元素数 |
| `cursor` | `cursorOf(state)`：工具对应的 CSS 光标 |
| `selectedCard` / `mindRoot` | 单选卡片 / 导图根节点 |
| `mindLayout` / `mindTheme` | 选中导图节点反查的布局与主题 |
| `votes` | `voteResults(state)`：票数前 8 |
| `presentItems` | 按当前演示模式生成序列 |
| `exportTargets` | 按导出范围取元素 |
| `canUndo` / `canRedo` | `past.length > 0` / `future.length > 0` |

## 新增一条命令的五步

1. **定类型**：在 `src/domain/commands/` 对应文件里加成员（新领域就新建文件），带 `& CommandMeta`。
2. **写 reducer**：同文件导出 `reduceX(board | file, cmd)`，未命中返回 `null`，内容未变返回原引用。
3. **挂注册表**：`src/domain/commands/command.ts` 导出类型与 reducer；`src/domain/reduce.ts` 把它加进 `fileReducers` 或 `boardReducers`。
4. **包 action**：在 `src/app/actions/` 对应模块里写函数，算好载荷后 `dispatch`，必要时组数组批量提交。
5. **补测试与文档**：在 `test/domain/commands/` 加用例（至少覆盖「生效」「无变化返回原引用」「边界」三种情形），更新本页命令表与 [模块地图](模块地图.md)。

改完跑 `npm run check && npm test && npm run build`。
