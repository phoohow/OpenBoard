# 目录结构与分层

本文给出 `src/` 的完整结构与逐目录职责，并说明依赖矩阵与守卫脚本的判定规则。找文件先看这里，找功能链路看 [模块地图](模块地图.md)。

## 分层与依赖方向

```
model ← geometry ← domain ← features ← app ← App.tsx
ui / canvas  只依赖 model / geometry / domain / features（以及同层）
```

依赖只能向右（下层不感知上层）。`ui` 与 `canvas` 是同层兄弟，彼此不得依赖，也不允许引用 `app`；它们在组件的 props 里用结构化类型声明自己需要的那几个 action（例如 `TopBar` 的 `actions.board.renameBoard`、`actions.present.startPresent`），真实的 `actions` 对象由 `App.tsx` 注入。这样既拿到了类型检查，又不会产生 `ui → app` 的导入。

## 依赖矩阵

`scripts/check-layers.mjs` 里的 `ALLOWED` 表就是唯一事实来源：

| 层 | 允许依赖 |
| --- | --- |
| `model` | `model` |
| `geometry` | `model`、`geometry` |
| `domain` | `model`、`geometry`、`domain` |
| `features` | `model`、`geometry`、`domain`、`features` |
| `app` | `model`、`geometry`、`domain`、`features`、`app` |
| `ui` | `model`、`geometry`、`domain`、`features`、`ui` |
| `canvas` | `model`、`geometry`、`domain`、`features`、`canvas` |
| `root`（`src` 根下的文件） | 以上全部 |

补充两条硬约束：

- `PURE_LAYERS = model / geometry / domain / features` 不得出现 `import ... from 'react'`，确保领域逻辑能在 Node 环境单测。
- `BANNED_SYMBOLS` 三条：`setElements(`、`EditorCtx`、`useCanvasPointer`。检出即失败，用来防止旧写入口回流。

## 路径与导入约定

- 别名 `@/*` 映射到 `src/*`（`tsconfig.json` 与 `vite.config.ts` 同步配置）。跨层引用一律用 `@/`；同目录同层用相对路径。
- 类型导入用 `import type`，`vite.config` 与 `tsconfig` 都开了 `isolatedModules`，混用会报错。
- 全项目不使用 barrel：导入直接指向实现文件（`@/domain/state`、`@/geometry/box`、`@/features/storage/file`），没有隐式目录入口。
- `@/domain/commands` 是命令定义的聚合点（联合类型与 reducer 表），属于模块本体而非转发壳。
- `src/app/actions.ts` 把 `actions/` 下十个动作模块聚成一个对象，是视图注入的唯一入口。

## 守卫脚本怎么判

```bash
npm run check
```

脚本做的事：

1. 递归遍历 `src` 下所有 `.ts` / `.tsx`。
2. 由路径推出所属层（`src/domain/x.ts` → `domain`，`src/App.tsx` → `root`）。
3. 对每条 `import ... from 'x'` / `import('x')`，把说明符解析成层：`@/` 前缀取第一段，相对路径按所在目录解析。
4. 若目标层不在白名单内，记录一条错误；若纯层出现 `from 'react'`，记录一条错误；若命中禁用符号，记录「文件:行号」。
5. 有任何错误就打印清单并 `process.exit(1)`。

常见违例与提示：

| 写法 | 报错 |
| --- | --- |
| `domain/x.ts` 里 `import { useState } from 'react'` | `domain 层不得依赖 react` |
| `features/x.ts` 里 `import { toast } from '@/app/actions/ui'` | `features 层不得依赖 app 层` |
| `canvas/x.tsx` 里 `import { TopBar } from '@/ui/layout/TopBar'` | `canvas 层不得依赖 ui 层` |
| 任意文件写 `setElements(...)` | `检出已删除符号 setElements(` |

守卫只检查导入与符号，不检查运行时副作用；「纯函数不读时钟、不写存储」靠 code review 与单测保证。
